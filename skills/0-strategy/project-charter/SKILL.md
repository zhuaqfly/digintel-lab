# 转型立项书与项目章程编制

## 核心原则
1. **立项书是"承诺文件"**：它是高层对项目目标、资源、边界的正式承诺，不是一纸空文
2. **范围要收敛**：第一期项目必须有明确的边界，什么做、什么不做，清清楚楚
3. **速赢设计**：立项书中必须设计3-6个月内能出成果的速赢项目，建立信心
4. **治理重于计划**：项目失败通常不是计划不好，而是治理机制缺失——谁决策、谁执行、谁负责必须明确
5. **风险前置**：立项时就要识别最大的3-5个风险，并给出预案，不要等出了问题再救火

---

## 触发条件
高层访谈完成、战略愿景基本对齐后，需要正式立项、签署项目章程、召开启动会时激活。

## 立项书输出框架（10个章节）

### 第1章：项目背景与动因
**内容要求**：
- 外部环境：行业趋势、政策要求、竞争格局变化、标杆案例
- 内部压力：业务痛点、增长瓶颈、效率问题、历史数字化项目复盘
- 触发事件：什么具体事件/决策促成了项目立项？
- 紧迫性：为什么是"现在"而不是"明年再说"？

**质量要求**：用数据和事实说话，不写"随着数字化浪潮"这种空话，要回答"不做会怎样"。

### 第2章：项目愿景与目标
**内容要求**：
- 引用战略屋的愿景陈述
- **业务目标**（3-5个，SMART原则）：
  - 每个目标有：基线值→目标值→达成时间→衡量方式
  - 示例：供应链库存周转率从4.2次/年提升到6.5次/年（24个月），通过ERP+APS系统数据衡量
- **能力建设目标**：建成什么平台、什么团队、什么机制
- **不做什么**（Out of Scope）：明确列出不在本项目范围内的事项，避免期望膨胀

### 第3章：项目范围
**内容要求**：
- **业务范围**：覆盖哪些业务单元/区域/产品线？第一期覆盖哪些？后续如何扩展？
- **功能范围**：建设哪些核心能力模块？（列清单）
- **技术范围**：涉及哪些系统？哪些新建？哪些改造？哪些集成？
- **数据范围**：哪些数据需要治理/打通/入湖？
- **组织范围**：哪些部门参与？哪些是核心部门？哪些是配合部门？

**范围边界工具——MoSCoW法则**：
| Must Have（必须有） | Should Have（应该有） | Could Have（可以有） | Won't Have（暂不做） |
|---------------------|----------------------|---------------------|---------------------|
| 第一期必须交付的核心能力 | 重要但可以推迟到第二期 | 锦上添花，资源允许才做 | 明确不在范围内，避免期望蔓延 |

### 第4章：核心价值与预期收益
**内容要求**：区分三种价值，避免只谈"降本增效"的空话

| 价值类型 | 说明 | 量化方式 |
|---------|------|---------|
| 财务价值 | 直接可量化的经济收益 | 成本节约xx万元、营收增加xx万元、ROI预期xx% |
| 业务价值 | 运营效率/客户体验改善 | 交付周期缩短xx%、客户满意度提升xx分 |
| 战略价值 | 长期能力建设 | 建成数据底座、培养xx名数字化人才、形成xx机制 |

**要求**：第一期至少有1-2个可量化的财务/业务价值（速赢价值），战略价值也不能少。

### 第5章：项目路线图与里程碑
**内容要求**：
- 总体周期（建议第一期6-12个月）
- 分阶段计划（典型分三阶段）：
  - **Phase 1（0-3月）：速赢+规划**——完成1-2个速赢场景交付，完成详细方案设计
  - **Phase 2（3-9月）：核心建设**——核心平台/系统上线，主要场景跑通
  - **Phase 3（9-12月）：规模推广**——从试点到全面推广，价值兑现
- 每个阶段的关键里程碑和交付物清单
- 速赢项目设计：选择业务痛点强、见效快、技术风险低的场景

**里程碑示例**：
| 时间 | 里程碑 | 交付物 | 验收标准 |
|------|--------|--------|---------|
| M1（第1月） | 项目启动 | 启动会召开、团队到位 | 全员周知项目启动 |
| M2（第3月） | 蓝图设计完成 | 详细方案设计文档 | 高管评审通过 |
| M3（第6月） | 核心系统上线 | xx平台V1.0上线 | 试点用户验收通过 |
| M4（第9月） | 速赢价值兑现 | xx场景运营数据 | 效率指标提升xx% |
| M5（第12月） | 一期验收 | 一期全部交付物 | 项目验收报告签署 |

### 第6章：治理结构与组织保障
**内容要求**：

```
┌─────────────────────────────────────────┐
│     指导委员会（Steering Committee）      │
│  主任：CEO/董事长（月度决策会）            │
│  成员：各业务VP、CFO、CIO、CDO            │
└───────────────┬─────────────────────────┘
                │
┌───────────────▼─────────────────────────┐
│     项目管理办公室（PMO）                 │
│  主任：CDO/项目总监（周例会）              │
│  职责：进度管控、风险升级、资源协调        │
└───────────────┬─────────────────────────┘
                │
    ┌───────────┼───────────┐
    ▼           ▼           ▼
┌────────┐ ┌────────┐ ┌────────┐
│业务组   │ │技术组   │ │变革组   │
│(业务负责人│ │(架构/开发│ │(培训/沟通│
│+关键用户)│ │+数据/AI) │ │+推广)   │
└────────┘ └────────┘ └────────┘
```

**关键角色说明**：
| 角色 | 人选 | 职责 | 时间投入 |
|------|------|------|---------|
| 项目Sponsor（最高发起人） | CEO/总裁 | 最终决策、资源协调、站台背书 | 月均4小时 |
| 项目Owner（业务负责人） | 业务VP/COO | 业务价值负责、需求决策、验收 | 周均4-8小时 |
| 项目经理/PMO负责人 | CDO/项目总监 | 日常管理、进度管控、风险管理 | 全职 |
| 业务关键用户 | 各业务部门骨干 | 需求确认、测试验收、内部推广 | 周均16小时 |
| 技术负责人 | CTO/架构师 | 技术方案、开发管控 | 全职/半职 |
| 外部顾问团队 | 咨询公司/供应商 | 方法论、最佳实践、交付支持 | 驻场 |

### 第7章：资源投入预算
**内容要求**：
- **人力投入**：内部人员FTE数量（按角色分）、外部团队规模
- **技术投入**：软件许可、云资源、硬件设备、数据采购（粗略量级）
- **咨询与服务**：咨询费、实施费、培训费
- **预算总额**：给出范围区间（如800-1200万），分年度预算
- **ROI测算**：预期收益/投入比，回本期

> 注意：立项阶段不需要精确到万元级，量级准确即可，详细预算在蓝图阶段细化。

### 第8章：风险管理
**内容要求**：识别项目Top 5-8风险，按"可能性×影响度"矩阵评估

| 风险描述 | 可能性 | 影响度 | 风险等级 | 应对策略 | 责任人 |
|---------|--------|--------|---------|---------|--------|
| 业务部门参与度不足，需求反复变更 | 高 | 高 | 🔴红 | Sponsor站台，业务负责人KPI绑定 | 项目Owner |
| 数据质量差，AI模型效果不达预期 | 中 | 高 | 🟡黄 | 提前启动数据治理，先做数据质量评估 | 数据负责人 |
| 关键用户时间投入不足 | 中 | 高 | 🟡黄 | 部门KPI联动，设置"金牌用户"激励 | 各业务负责人 |
| 技术选型失误导致后期架构重构 | 低 | 高 | 🟡黄 | 概念验证（POC）先行，架构评审机制 | 技术负责人 |
| 员工抵触，系统使用率低 | 高 | 中 | 🟡黄 | 变革管理提前介入，培训+激励 | 变革负责人 |

### 第9章：成功标准与验收
**内容要求**：
- **项目成功**：按范围/时间/预算/质量交付（传统铁三角）
- **业务成功**：业务指标达成（目标值兑现率>80%）
- ** adoption成功**：系统使用率、用户满意度、流程覆盖率
- **验收机制**：谁验收、验收什么、验收流程、验收标准

### 第10章：下一步行动
**内容要求**：立项书签署后30天内的具体行动项
- 项目团队到位时间表
- 启动会筹备计划
- 详细方案设计（蓝图）工作计划
- 速赢项目启动安排

## 项目章程核心条款（简版，附在立项书后）

```
# 数智化转型项目章程

## 第一条 项目名称与编号
xxx公司数智化转型一期项目，编号：xxx-2026-001

## 第二条 项目Sponsor与Owner
- Sponsor：xxx（CEO）
- 业务Owner：xxx（COO）
- 项目经理：xxx

## 第三条 决策机制
- 指导委员会：每月一次，重大决策（范围变更、预算调整、阶段验收）
- PMO周会：每周一次，进度跟踪、问题协调、风险升级
- 项目组站会：每日15分钟，当日进度同步

## 第四条 变更控制
- 范围变更>10人天 必须提交CR（Change Request），PMO审核，指导委员会审批
- 任何需求变更必须书面化，禁止"口头加需求"

## 第五条 沟通机制
- 月度报告：向指导委员会汇报进度/风险/成果
- 双周简报：向中层管理者同步项目进展
- 即时沟通：项目企微/飞书群，日常问题当日响应

## 第六条 签署
Sponsor签字：___________  日期：______
业务Owner签字：_________  日期：______
项目经理签字：___________  日期：______
```

## 启动会（Kick-off）材料大纲
1. **为什么做**（5分钟）：Sponsor站台，讲转型背景与决心
2. **做什么**（10分钟）：项目负责人讲愿景、目标、范围、价值
3. **怎么做**（10分钟）：项目经理讲路线图、里程碑、方法论
4. **谁来做**（5分钟）：介绍核心团队、治理结构、各方职责
5. **需要什么支持**（5分钟）：对各部门的期望与配合要求
6. **Q&A**（10分钟）：答疑

## 质量检查清单
- [ ] 立项书是否明确回答了"为什么做、做什么、怎么做、谁来做、花多少钱、有什么风险"？
- [ ] 项目范围是否清晰？Out of Scope是否明确？
- [ ] 是否设计了3-6个月的速赢项目？
- [ ] 治理结构是否明确到具体人名？Sponsor是否是真正的一把手？
- [ ] 资源预算是否给出了合理的量级？
- [ ] Top风险是否都有应对策略和责任人？
- [ ] 成功标准是否可衡量？
- [ ] 项目章程是否有Sponsor签字栏？
