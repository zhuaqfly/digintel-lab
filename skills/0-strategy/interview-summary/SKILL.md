# 高层访谈纪要整理方法论

高层访谈纪要不是简单的录音转写，而是将分散、口语化、情绪化的高管表达提炼为结构化、可决策的战略输入。纪要质量直接决定后续诊断结论与方案设计的准确性。本方法论参考麦肯锡"洞察萃取"与BCG"高管信号识别"框架，确保从原始访谈笔记到战略洞察的高效转化。

## 一、纪要标准结构

按角色分章节（CEO→COO→CIO→CFO→其他高管），每个角色章节统一包含以下五个模块：

### 1.1 核心诉求
按优先级排序高管明确表达的3-5项核心诉求，标注紧迫度（H/M/L）和业务影响范围。诉求需还原为"动词+对象+目标"的标准句式，如"三年内将运营成本降低20%"而非"降本增效"。

### 1.2 关键痛点
区分"表象痛点"与"根因痛点"：表象痛点是高管直接抱怨的问题，根因痛点是经过追问后暴露的底层矛盾。每个痛点标注影响层级（战略层/管理层/执行层）和影响周期（长期/中期/短期）。

### 1.3 原话引述（带情绪信号）
保留关键原话并标注情绪信号强度：
- 🔴 强信号：明确表态（"必须""绝不""一定要"）、重复强调（同一点提到≥3次）、肢体语言（拍桌/前倾/皱眉/叹气）、时间锚点（"今年内""Q3之前"）。影响优先级最高，必须在战略设计中回应。
- 🟡 中信号：隐含态度（"也许可以""有人提到"）、侧面提及（在回答其他问题时顺带说）、条件性表述（"如果……也许……"）。需在后续诊断中进一步追问验证。
- 🟢 弱信号：随口提及、不确定表述（"可能吧""不太清楚"）、假设性畅想。记录在案但不作为结论依据。

### 1.4 期望成果
将高管期望分为三类：**硬成果**（可量化：营收、成本、效率指标）、**软成果**（可感知：文化、竞争力、品牌）、**风险规避**（不能发生的事：系统宕机、人员流失、合规事故）。

### 1.5 底线顾虑
明确标注"红线议题"：预算上限、组织敏感点、业务连续性要求、个人政治风险。红线议题是方案设计的硬约束。

## 二、观点对比矩阵

跨角色对比是纪要是最有价值的产出，采用四维对比矩阵：

| 对比维度 | CEO | COO | CIO | CFO | 信号标记 |
|---------|-----|-----|-----|-----|---------|
| 转型动机 | | | | | ✓共识 / ⚠分歧 |
| 转型期望 | | | | | ✓共识 / ⚠分歧 |
| 核心顾虑 | | | | | ✓共识 / ⚠分歧 |
| 投入意愿 | | | | | ✓共识 / ⚠分歧 |

**共识判定标准**：四个高管中有≥3人观点一致，标记为✓共识，作为战略设计的确定输入。
**分歧判定标准**：关键议题上出现明显对立（如CEO要"all in AI"而CFO要"严控预算"），标记为⚠分歧，需在战略对齐会上专项讨论解决。

## 三、信号识别操作清单

| 信号类型 | 识别特征 | 记录方式 | 后续动作 |
|---------|---------|---------|---------|
| 🔴强信号 | 祈使句/绝对化词语/重复/肢体动作 | 原文+语境+情绪标注 | 立即纳入战略洞察，方案必须回应 |
| 🟡中信号 | 条件句/被动语态/转折后内容 | 标注推测含义 | 设计验证性问题，二次访谈追问 |
| 🟢弱信号 | 假设句/题外话/否定后内容 | 附录记录 | 观察后续是否升级，暂不行动 |

**关键信号词清单**：强信号词——"必须""一定要""不能接受""生死存亡""底线""最后一次机会"；中信号词——"希望""考虑""或许""看看吧""原则上"；弱信号词——"可能""大概""听说""别人在做"。

## 四、战略洞察提炼

基于全部访谈，提炼3-5条核心洞察和1-3个速赢机会：

**核心洞察模板**："基于[事实/信号]，我们判断[洞察结论]，这意味着[战略含义]。"
洞察需满足MECE原则（相互独立、完全穷尽），避免泛泛而谈。例如：
- "CEO将AI转型视为'第二曲线'而非效率工具，这意味着需要独立的预算和组织保障，而非嵌入现有IT体系。"
- "COO与CIO在'数据驱动决策'上存在认知鸿沟，前者要结果后者讲技术，这意味着数据治理需从业务场景入手而非平台建设先行。"

**速赢机会判定**：同时满足三个条件——①多位高管提及 ②实施周期<6个月 ③投入<预算10%。速赢机会是Phase 1项目选择的关键输入。

[四维对比表+共识/分歧标注]

## 使用流程
1. 访谈结束24小时内完成单角色纪要初稿，趁记忆清晰补充语境
2. 全部访谈完成后进行跨角色对比，标记共识与分歧
3. 召开内部洞察讨论会，对强信号进行二次确认
4. 输出最终纪要，作为诊断报告和立项书的核心输入
