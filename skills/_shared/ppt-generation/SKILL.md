# 咨询报告PPT生成

## 触发条件
当需要将咨询报告转化为PPT演示文稿时激活。典型场景: 咨询交付物准备、项目汇报、管理层汇报。

## 前置条件
- 已有咨询报告内容(来自 consulting-workflow 或单个 skill)
- Node.js 20+ 和 npm
- 导出 PPTX 需要本机有 Chrome/Chromium/Edge

## 依赖安装

首次使用前需安装 dashi-ppt-skill:
```bash
npx dashi-ppt-skill@latest
```
国内网络:
```bash
npx --registry=https://registry.npmmirror.com dashi-ppt-skill@latest
```

## 工作机制

### 内容映射黄金规则(必须遵守)

**规则1: 数据完整性优先于版式美观**
- 如果报告有7个维度,但模板页只有4个槽位 → 必须换用能容纳7项的layout,或拆成2页
- **绝不截断数据**。宁可多一页,不可少一项。

**规则2: 每个数据必须可追溯**
- PPT中的每个关键数字必须标注来源(在note/asideTag/sub等字段中)
- 格式: "数据来源: {机构名}{时间}{报告名}"
- 如果数据是agent计算的(如综合评分),必须注明计算方法

**规则3: 图表数据必须有逻辑依据**
- 散点图/气泡图的坐标值(x/y)不能凭空编造
- 必须注明: x轴=什么维度(0-100分), y轴=什么维度(0-100分), 每个点的评分依据
- 数据点应分散在多个象限,不能全部挤在一个区域

**规则4: 同一数据跨页一致**
- 成熟度评分在摘要页=3.14,在详情页也必须=3.14
- 七维度评分在摘要页和详情页必须完全一致
- 如果有总分,必须与分项的加权计算结果一致

**规则5: 术语首次出现时解释**
- L3 → "L3(指标穿透级): 统一指标,多层下钻"
- 5A架构 → "管控+业务+数据+应用+技术五层架构"
- POC → "POC(概念验证): 小范围验证AI场景效果"

**规则6: 页面标题必须有观点输出(最关键)**
- 每页的标题/badge/kicker不是topic名称,而是该页的核心观点
- ❌ "行业定位" → ✅ "自动化领先但全域治理不足"
- ❌ "数据资产盘点" → ✅ "120+项资产,5个断点制约价值释放"
- ❌ "差距分析" → ✅ "11项差距,P0三项阻塞转型"
- ❌ "转型路线图" → ✅ "三阶段3.2亿,筑基→跃升→引领"
- 标题要让读者一眼抓住该页的核心结论

**规则7: 页面头部结构统一**
- 所有内容页(非封面/非结尾)使用统一的头部格式: 章节编号 + 观点标题
- 使用head字段: {no:"01", en:"English Title", cn:"中文观点标题"}
- 章节编号按报告逻辑连续编号(01,02,03...),不跳号不重号
- 封面页和结尾页不需要章节编号
- 同一PPT中不要混用 badge/kicker 格式和 head.no/en/cn 格式

**规则8: 避免空内容区域**
- 如果layout有media槽位(图片/视频),但没有实际图片资源 → 不要用该layout,换用无media槽位的layout
- 检查layout的fillPlan.media数组,如果visibleCount > 0且没有图片 → 换layout
- 每个页面区域都要有内容,不能出现空白区域

### 报告到PPT的映射规则

咨询报告的结构化内容按以下规则映射为PPT页面:

| 报告章节 | PPT页面类型 | dashi-ppt版式 | 说明 |
|---------|-----------|-------------|------|
| 报告标题 + 企业信息 | 封面 | cover | 标题+副标题+日期+保密级别 |
| 报告目录 | 目录页 | toc | 各章节标题(完整,不截断) |
| 执行摘要 | 指标页 | metrics | 核心结论3-5点(每点有数据支撑) |
| 成熟度评估总览 | 对比页 | comparison | 当前vs目标,含计算方法说明 |
| 七维度评分(完整7项) | 数据页 | data/trend | **必须显示全部7项**,槽位不足则拆页 |
| 成熟度雷达图 | 趋势页 | trend | 七维度雷达图数据 |
| AI就绪度评分 | 对比页 | comparison | 四维度评分+就绪级别+阻塞点 |
| 标杆企业对标 | 对比页 | comparison | 标杆举措+成效+借鉴点(每家3项) |
| 数据资产盘点 | 指标页 | metrics | 资产数量+质量评分+断点清单 |
| 差距分析 | 风险页 | risk | P0-P3差距清单(按优先级,含闭合建议) |
| 差距闭合路线图 | 流程页 | process | 三阶段时间轴(含里程碑) |
| 投资ROI | 指标页 | metrics | 分阶段投资+收益+ROI+回收期 |
| 风险评估 | 矩阵页 | matrix | 风险×概率×影响+应对措施 |
| 综合建议 | 流程页 | process | 三阶段路线图+预期成效 |
| 结尾页 | 结尾 | ending | 致谢+联系方式+信息来源 |

### 主题选择指南

| 咨询场景 | 推荐主题 | 理由 |
|---------|---------|------|
| 央国企/政府 | 深蓝杂志 | 稳重、专业 |
| 制造业/工业 | 轻拟态 | 清晰、务实 |
| 金融/咨询 | 黑金实验 | 高端、商务 |
| 互联网/科技 | 炫光紫绿 | 现代、科技感 |
| 通用场景 | 玻璃糖果 | 简洁、亲和 |

## 执行流程

### 步骤1: 报告内容解析
- 输入: 咨询报告 markdown
- 处理:
  1. 识别报告结构(章节标题、表格、列表)
  2. 提取核心数据(评分、等级、差距数量等)
  3. 提取关键结论和建议
  4. 确定PPT页数(默认: 报告章节数 + 封面目录结尾)
- 输出: PPT内容大纲(每页标题+要点)

### 步骤2: 页面规划
- 输入: PPT内容大纲
- 处理:
  1. 按映射规则为每页选择版式(cover/toc/metrics/trend/comparison/risk/process/ending)
  2. 为数据型页面准备图表数据(雷达图/柱状图/表格)
  3. 选择视觉主题(根据行业或用户偏好)
  4. 确定页面顺序
- 输出: PPT页面规划表

### 步骤3: 调用 dashi-ppt-skill 生成
- 输入: PPT页面规划表 + 主题选择
- 处理:
  1. 调用 dashi-ppt-skill
  2. 传入结构化内容(每页的标题、内容、版式、数据)
  3. 选择主题风格
  4. 等待生成完成
- 输出: 网页版PPT编辑器(HTML)

### 步骤4: 导出PPTX
- 输入: 生成的PPT项目目录
- 处理:
  ```bash
  npm --prefix <项目目录> run export:pptx -- <输出目录>/咨询报告.pptx
  ```
- 输出: 可编辑 .pptx 文件

### 步骤5: 质量检查
- 输入: 生成的PPTX
- 处理:
  1. 检查页数是否完整
  2. 检查关键数据是否正确(评分、等级、差距数量)
  3. 检查图表是否渲染正确
  4. 检查文字是否有截断
- 输出: 质量检查报告(如有问题则调整重新生成)

## 输出模板

### PPT内容大纲模板

```
第1页 - 封面
  标题: {企业名称} 数智化转型咨询报告
  副标题: {咨询范围} | {日期}
  版式: cover

第2页 - 目录
  内容: 报告各章节
  版式: toc

第3页 - 执行摘要
  核心结论: {1-3句话}
  关键发现: {3-5个要点}
  建议优先行动: {3条}
  版式: metrics

第4页 - 成熟度评估
  当前等级: L{X}
  综合得分: {X.X}/5.0
  七维度评分: {表格数据}
  版式: metrics + comparison

第5页 - 成熟度雷达图
  数据: {七维度评分JSON}
  版式: trend (雷达图)

第6页 - AI就绪度诊断
  综合就绪度: {级别}
  四维度评分: {表格}
  关键阻塞点: {列表}
  版式: metrics

第7页 - 差距分析
  P0差距: {列表}
  P1差距: {列表}
  版式: risk

第8页 - 数据资产盘点
  资产总数: {N}项
  质量评分: {X.X}/5.0
  高价值资产: {列表}
  版式: metrics

第9页 - 综合建议与路线图
  第一阶段({时间}): {要点}
  第二阶段({时间}): {要点}
  第三阶段({时间}): {要点}
  版式: process

第10页 - 结尾
  版式: ending
```

## 降级策略
- dashi-ppt-skill 未安装 → 提示用户运行安装命令,或改为输出markdown格式的大纲(用户自行制作PPT)
- PPTX导出失败(无Chrome) → 仅输出HTML版编辑器,提示用户在浏览器中查看和编辑
- 报告内容不足 → 基于已有内容生成精简版PPT(封面+摘要+核心结论+结尾)
- 图表数据不完整 → 用文字+表格替代图表

## 关联 Skill
- 上游:

  - `maturity-assessment` 等单个skill — 提供专项报告
- 下游: 无(最终交付物)
