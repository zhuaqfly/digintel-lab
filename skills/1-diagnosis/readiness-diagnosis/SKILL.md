# AI就绪度诊断

## 触发条件
当需要评估企业是否具备引入AI应用的条件时激活。典型场景: AI转型规划前、AI场景选型前、AI项目立项前。

## 前置条件
- 已了解企业基本业务和数据现状
- 如有 maturity-assessment 结果可直接承接

## 评估模型: 四维就绪度框架

### 四大维度及子维度

**1. 数据就绪度 (Data Readiness)**
- 数据采集覆盖: 核心业务数据是否已数字化采集
- 数据质量: 完整性、准确性、一致性、时效性
-数据治理: 标准统一、元数据管理、数据血缘
- 数据共享: 跨系统数据贯通程度、数据服务能力
- 数据规模: 是否有足够的训练/分析数据量

**2. 技术就绪度 (Technology Readiness)**
- 算力基础: GPU/ CPU资源、弹性计算能力
- 平台能力: AI平台、模型训练/推理环境
- 系统集成: API开放程度、微服务架构、系统互联
- 安全合规: 数据安全、模型安全、信创适配

**3. 组织就绪度 (Organization Readiness)**
- 领导层认知: 管理层对AI的理解和支持程度
- 人才储备: 数据工程师、AI工程师、业务分析师数量
- 组织机制: 是否有AI专项团队、跨部门协作机制
- 文化准备: 员工对AI的接受度、试错文化

**4. 场景就绪度 (Scenario Readiness)**
- 场景清晰度: 是否有明确的AI应用场景需求
- 业务价值: 场景的业务价值和ROI预期
- 数据可获得: 目标场景所需数据是否可获取
- 可验证性: 场景效果是否可量化评估

### 评分标准
每个子维度 1-5 分:
- 1分: 完全不具备
- 2分: 初步具备,大量缺口
- 3分: 基本具备,部分缺口
- 4分: 较好具备,少量缺口
- 5分: 完全具备,可支撑AI落地

## 执行流程

### 步骤1: 数据就绪度评估
- 输入: 数据基础设施现状
- 处理:
  1. 评估核心业务数据数字化采集覆盖率
  2. 评估数据质量(完整性/准确性/一致性/时效性)
  3. 评估数据治理水平(标准/元数据/血缘)
  4. 评估数据共享和贯通程度
  5. 评估数据规模是否满足AI应用需求
- 输出: 数据就绪度评分(5个子维度) + 关键缺口清单

### 步骤2: 技术就绪度评估
- 输入: IT基础设施现状
- 处理:
  1. 评估算力资源(GPU/CPU/弹性计算)
  2. 评估AI平台和模型环境
  3. 评估系统集成能力和API开放程度
  4. 评估安全合规和信创适配情况
- 输出: 技术就绪度评分(4个子维度) + 技术缺口清单

### 步骤3: 组织就绪度评估
- 输入: 组织与人才现状
- 处理:
  1. 评估管理层对AI的认知和支持程度
  2. 盘点AI相关人才(数据工程师/AI工程师/业务分析师)
  3. 评估组织机制(AI团队/跨部门协作)
  4. 评估组织文化和员工接受度
- 输出: 组织就绪度评分(4个子维度) + 组织缺口清单

### 步骤4: 场景就绪度评估
- 输入: 企业基本信息 + 业务需求描述
- 处理:
  1. 识别企业潜在的AI应用场景
  2. 评估场景的业务价值和ROI
  3. 评估场景所需数据的可获得性
  4. 评估场景效果的可验证性
- 输出: 场景就绪度评分(4个子维度) + 优先场景清单

### 步骤5: 综合诊断与路径建议
- 输入: 四维度评分
- 处理:
  1. 计算综合就绪度得分
  2. 识别关键阻塞维度(最低分维度)
  3. 判定就绪级别:
     - 综合分 < 2.0 → 未就绪(需基础设施补课)
     - 2.0-3.0 → 初步就绪(可选低门槛场景试点)
     - 3.0-4.0 → 基本就绪(可系统推进AI应用)
     - > 4.0 → 充分就绪(可规模化推广AI)
  4. 给出就绪路径建议
- 输出: 综合诊断结论 + 就绪路径

## 降级策略
- 缺少成熟度评估结果 → 独立进行就绪度评估,不依赖前置Skill
- IT基础设施信息不足 → 技术维度标注"待补充",其他维度正常评估
- 组织信息不足 → 基于行业平均水平推断,标注"推断数据"

## 关联 Skill
- 上游: `maturity-assessment` (成熟度评估) — 提供整体成熟度背景
- 下游:
  - `scenario-identification` (场景识别) — 基于就绪度推荐适合的AI场景
  - `data-governance` (数据治理) — 针对数据缺口制定治理方案
  - `top-level-design` (顶层设计) — 基于就绪度制定转型蓝图
