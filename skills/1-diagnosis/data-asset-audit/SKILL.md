# 数据资产盘点

## 触发条件
当需要全面了解企业数据资产现状时激活。典型场景: 数据治理项目启动、数据中台建设前、AI应用数据准备。

## 前置条件
- 已获取企业系统清单和数据库信息
- 了解企业业务架构和价值链

## 盘点框架

### 数据资产分类

| 类别 | 说明 | 示例 |
|------|------|------|
| 主数据 | 描述业务实体的核心数据 | 客户、产品、供应商、组织 |
| 交易数据 | 业务活动产生的记录 | 订单、发票、工单、合同 |
| 参考数据 | 标准化的分类和编码 | 行业代码、币种、地区 |
| 分析数据 | 加工后的统计/分析数据 | 报表指标、聚合数据、标签 |
| 元数据 | 描述数据的数据 | 表结构、字段定义、数据血缘 |
| 非结构化数据 | 文档/图片/音视频 | 合同PDF、设计图纸、监控视频 |

### 数据质量六维度

1. **完整性**: 数据记录是否齐全,关键字段是否为空
2. **准确性**: 数据值是否正确反映真实情况
3. **一致性**: 跨系统同一数据是否一致
4. **时效性**: 数据是否及时更新,是否过期
5. **唯一性**: 是否存在重复记录
6. **合规性**: 数据采集和使用是否符合法规要求

## 执行流程

### 步骤1: 业务域划分
- 输入: 企业业务架构
- 处理:
  1. 按价值链梳理业务域(研发/采购/生产/营销/销售/服务/财务/人力)
  2. 确认每个业务域的核心业务实体和活动
  3. 建立业务域-系统映射关系
- 输出: 业务域-系统映射表

### 步骤2: 数据资产识别
- 输入: 系统清单 + 数据库清单 + 业务域映射
- 处理: 对每个系统/数据库:
  1. 识别数据资产(表/文件/API/流数据)
  2. 分类数据资产(主数据/交易数据/参考数据/分析数据/非结构化)
  3. 记录数据资产基本信息(名称/类型/来源/更新频率/数据量)
  4. 识别数据Owner和使用者
- 输出: 数据资产清单(原始)

### 步骤3: 数据流向梳理
- 输入: 数据资产清单 + 系统集成关系
- 处理:
  1. 梳理数据在各系统间的流向(谁产生→谁使用)
  2. 识别数据汇聚点和分发点
  3. 发现数据断点(应打通但未打通的数据流)
  4. 发现数据冗余(多处存储同一数据)
- 输出: 数据流向图 + 断点/冗余清单

### 步骤4: 数据质量评估
- 输入: 数据资产清单 + 抽样数据(如有)
- 处理: 对关键数据资产:
  1. 评估完整性(关键字段空值率)
  2. 评估准确性(抽样校验)
  3. 评估一致性(跨系统比对)
  4. 评估时效性(更新延迟)
  5. 评估唯一性(重复率)
  6. 评估合规性(敏感数据识别)
  7. 综合评分: 优(≥4分) / 良(3-4分) / 中(2-3分) / 差(<2分)
- 输出: 数据质量评分表

### 步骤5: 数据价值评估
- 输入: 数据资产清单 + 质量评分
- 处理: 对每类数据资产:
  1. 评估业务价值(支撑哪些业务/决策)
  2. 评估使用频率(高频/中频/低频)
  3. 评估AI应用潜力(是否适合训练模型/分析)
  4. 评估数据稀缺性(是否独有/难以获取)
  5. 标记高价值数据资产(优先治理和保护)
- 输出: 数据价值评级表

### 步骤6: 治理建议
- 输入: 全部前置输出
- 处理:
  1. 针对数据断点给出集成建议
  2. 针对数据冗余给出统一建议
  3. 针对质量问题给出治理优先级
  4. 针对高价值资产给出保护建议
  5. 制定数据治理分步计划
- 输出: 数据治理建议书

## 降级策略
- 无法访问实际数据库 → 基于系统文档和业务访谈推断数据资产,标注"待验证"
- 抽样数据不可获取 → 质量评估基于制度和流程推断,标注"定性评估"
- 系统清单不完整 → 盘点已知系统,标注"可能存在未覆盖系统"

## 关联 Skill
- 上游: `maturity-assessment` — 提供数据基础维度背景
- 下游:
  - `data-governance` (数据治理) — 基于盘点结果制定治理体系
  - `scenario-identification` (场景识别) — 基于数据资产推荐AI场景
  - `ai-architecture-design` (AI架构设计) — 基于数据资产设计数据架构
