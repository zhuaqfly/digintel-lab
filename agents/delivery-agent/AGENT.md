# 咨询交付物生成 Agent

## 触发条件
当需要将咨询报告转化为交付物时激活。典型场景:
- "把报告做成PPT"
- "生成一页纸执行摘要"
- "准备董事会汇报材料"

## 工作机制

```
咨询报告(来自专业Agent)
    ↓
[1. 内容分析] 解析报告结构、提取核心信息
    ↓
[2. 受众适配] 根据受众调整内容深度和表达方式
    ↓
[3. 交付物生成] 按选择的类型生成对应交付物
    ↓
[4. 质量检查] 检查内容完整性、数据一致性、排版质量
```

## 执行流程

### 步骤1: 内容分析与信息提取
- 输入: 咨询报告 markdown
- 处理:
  1. 识别报告类型(诊断/规划/治理/场景/组织)
  2. 提取核心结论(3-5条)
  3. 提取关键数据(评分、金额、数量等)
  4. 提取战略洞察和建议
  5. 提取路线图和里程碑
- 输出: 内容摘要(结构化的核心信息)

### 步骤2: 受众适配
- 输入: 内容摘要 + 受众信息
- 处理:
  - **董事会级**: 聚焦战略洞察、投资回报、风险,1页摘要+10页PPT
  - **管理层级**: 聚焦举措、路线图、资源,完整报告+15-20页PPT
  - **执行层级**: 聚焦行动方案、职责、时间表,详细文档
- 输出: 受众适配的内容大纲

### 步骤3: 交付物生成

#### 3a. PPT生成(调用ppt-generation skill)
- 按报告类型选择PPT页面规划:

| 报告类型 | PPT页数 | 页面规划 |
|---------|---------|---------|
| 诊断报告 | 12-15页 | 封面→行业背景→成熟度评估→就绪度诊断→差距分析→战略洞察→路线图→结尾 |
| 顶层规划 | 15-20页 | 封面→愿景目标→业务架构→技术架构→转型举措→路线图→投资ROI→风险→结尾 |
| 数据治理 | 12-15页 | 封面→现状诊断→治理体系→标准体系→质量管理→实施路线→组织保障→结尾 |
| 场景规划 | 15-20页 | 封面→行业趋势→场景全景→优先级矩阵→TOP场景→POC方案→推广策略→结尾 |
| 组织变革 | 12-15页 | 封面→现状诊断→组织设计→人才规划→变革管理→培训体系→路线图→结尾 |

- 主题选择: 央国企→深蓝杂志(theme09),科技企业→炫光紫绿(theme02)
- 调用 dashi-ppt-skill 生成HTML→导出PPTX

#### 3b. 执行摘要生成
- 格式: 1-2页 markdown
- 结构:
  ```markdown
  # {企业名称} {咨询类型} 执行摘要

  ## 一句话结论
  > {核心结论}

  ## 关键发现
  1. {发现1}: {数据支撑}
  2. {发现2}: {数据支撑}
  3. {发现3}: {数据支撑}

  ## 核心建议
  | 优先级 | 建议 | 预期成效 | 时间 |
  |--------|------|---------|------|
  | P0 | {建议} | {成效} | {时间} |

  ## 投资概览
  - 总投资: {金额}
  - 预期ROI: {X}%
  - 回收期: {N}年

  ## 下一步行动
  1. {行动1}
  2. {行动2}
  ```

#### 3c. 完整报告整理
- 格式: 完整 markdown
- 在原始报告基础上补充:
  - 封面页(企业名、报告类型、日期、保密级别)
  - 目录
  - 图表编号和引用
  - 附录(数据明细、方法论说明)

### 步骤4: 质量检查(关键步骤,不可跳过)

#### 4a. 数据一致性校验
逐页检查PPT中的数据与报告原文是否一致:
1. **数值一致性**: PPT中的评分/金额/数量必须与报告完全一致,不得四舍五入或近似
2. **逻辑一致性**: 同一指标在不同页面出现时数值必须一致(如成熟度评分在摘要页和详情页必须相同)
3. **计算一致性**: 如果PPT显示了总分,必须与各分项的加权计算结果一致,且要在PPT上注明计算方法

#### 4b. 内容完整性校验
逐页检查是否有信息丢失:
1. **维度完整性**: 如果报告有7个维度,PPT不得只显示4个 → 必须换用能容纳7项的layout,或拆成2页
2. **数据来源标注**: 每个关键数据必须标注来源(如"数据来源:交通运输部2026年3月《智慧港口等级评价指南》"),不能只有数字没有出处
3. **图表可读性**: 
   - 坐标轴必须有明确含义说明(x轴是什么、y轴是什么、刻度代表什么)
   - 坐标值必须有评分依据(不能凭空编造,要注明"基于XX维度评分计算")
   - 图表数据点要分散在有意义的区域,不能全部挤在一个象限
4. **术语解释**: PPT中出现的专业术语(如L3、5A架构)首次出现时要有简短解释

#### 4c. 排版检查
1. 检查文字是否截断(超出maxChars)
2. 检查图表是否渲染正确
3. 检查页数和内容完整性

#### 4d. 校验不通过的处理
- 数据不一致 → 修正PPT数据,重新生成
- 维度不完整 → 换layout或拆页,重新生成
- 坐标无依据 → 补充评分维度和计算方法,或换用表格替代散点图
- 数据无来源 → 补充来源标注
- **如果某项内容无法在PPT模板中完整呈现 → 在PPT中放摘要+详情指引,完整数据放在附录页**

## 降级策略
- dashi-ppt-skill 不可用 → 输出PPT大纲(markdown),用户可自行制作PPT
- 报告内容不足 → 基于已有内容生成精简版交付物,标注"完整版待补充"
- 多种交付物同时需要 → 按优先级依次生成(PPT > 执行摘要 > 完整报告)
