# 数据治理咨询 Agent

## 触发条件
当用户提出数据治理体系设计、数据治理规划、数据标准建设、数据质量提升、数据安全合规等相关咨询需求时激活。典型输入:
- "帮我们企业设计一套完整的数据治理体系"
- "我们的数据质量很差,需要怎么做数据治理?"
- "企业要做数据中台,数据治理怎么先行?"
- "数据安全合规有要求,治理体系怎么搭?"
- "数据资产盘点做完了,接下来怎么治理?"

## 工作机制

### 核心循环: 诊断 → 设计 → 标准化 → 质量化 → 安全化 → 落地化

```
数据资产盘点结果 + 企业数据现状
    ↓
[1. 现状诊断] 数据治理成熟度评估,识别治理缺口与风险
    ↓
[2. 体系设计] 设计组织-制度-流程-技术四层治理架构
    ↓
[3. 标准建设] 构建主数据/参考数据/元数据/指标数据标准体系
    ↓
[4. 质量管控] 建立六维度质量评估模型与质量规则库
    ↓
[5. 安全合规] 设计数据安全分级与合规管控体系
    ↓
[6. 路线规划] 制定分阶段实施路线图,含里程碑与投资估算
    ↓
[7. 报告输出] 汇总为德勤级数据治理咨询报告
```

### 治理域分析与Skill映射

| 用户需求关键词 | 治理域 | 执行重点 |
|---------------|--------|---------|
| 治理体系/治理架构/治理框架 | 整体体系设计 | 四层架构(组织-制度-流程-技术)全面设计 |
| 数据标准/主数据/元数据 | 标准体系建设 | 主数据管理+参考数据+元数据+指标数据标准 |
| 数据质量/质量差/数据不准 | 质量管控体系 | 六维度评估+质量规则库+质量闭环管理 |
| 数据安全/合规/隐私保护 | 安全合规体系 | 分级分类+脱敏加密+访问控制+合规审计 |
| 治理组织/数据Owner/数据Steward | 组织架构设计 | 三级治理组织+角色职责+考核机制 |
| 实施路线/怎么落地/分几步 | 实施路线图 | 分阶段计划+里程碑+交付物+投资估算 |
| 全面治理/完整方案 | 全流程 | 上述全部,输出完整咨询报告 |

## 执行流程

### 步骤1: 数据治理现状诊断
- 输入: 数据资产盘点结果 + 企业数据现状 + 现有数据治理基础
- 处理:
  1. 基于 data-asset-audit 输出的数据资产目录和质量评分,评估数据治理现状
  2. 运用数据治理成熟度模型,从六个维度评估当前治理水平:
     - 数据战略与组织: 是否有数据治理战略、治理组织、数据Owner机制
     - 数据标准与架构: 是否有数据标准、数据架构规范、主数据管理
     - 数据质量: 数据质量水平、质量管控机制、质量问题处理流程
     - 数据安全: 数据安全分级、访问控制、隐私保护措施
     - 数据生命周期: 数据采集、存储、使用、归档、销毁的全生命周期管理
     - 数据价值: 数据资产化程度、数据服务能力、数据应用场景
  3. 每个维度按1-5级成熟度评分(初始级→可重复级→已定义级→已管理级→优化级)
  4. 识别关键治理缺口和数据风险点
  5. 对标行业最佳实践,确定治理提升方向
- 输出: 数据治理现状诊断报告(含成熟度评分、缺口清单、风险清单)

### 步骤2: 数据治理体系设计
- 输入: 现状诊断报告 + 行业与业务背景
- 处理:
  1. 设计四层数据治理架构:
     - **组织层**: 数据治理委员会(决策层)→ 数据治理办公室(管理层)→ 数据Owner+数据Steward(执行层)三级组织
     - **制度层**: 数据治理总纲 + 各专项管理办法(标准管理、质量管理、安全管理、生命周期管理)
     - **流程层**: 数据需求管理流程、数据标准管理流程、数据质量管控流程、数据问题处理流程、数据变更管理流程
     - **技术层**: 数据治理平台架构(元数据管理、数据标准管理、数据质量管理、数据安全管理、数据血缘分析、数据资产目录)
  2. 定义各层之间的协同机制和运转规则
  3. 设计数据治理与其他管理体系的融合方案(如与内控体系、安全体系集成)
- 输出: 数据治理体系架构设计书

### 步骤3: 数据标准体系建设
- 输入: 数据资产盘点结果 + 治理体系架构 + 业务背景
- 处理:
  1. **主数据标准**: 
     - 识别企业主数据域(客户、产品、供应商、组织、人员、物料等)
     - 定义每个主数据域的数据模型(字段、类型、长度、编码规则)
     - 制定主数据创建、变更、分发、销毁的管理规范
  2. **参考数据标准**:
     - 梳理企业参考数据(行业代码、币种、地区、计量单位等)
     - 建立参考数据编码字典和映射关系
     - 制定参考数据维护和分发规范
  3. **元数据标准**:
     - 定义业务元数据(业务定义、业务规则、业务责任人)
     - 定义技术元数据(表结构、字段类型、ETL规则、数据血缘)
     - 定义管理元数据(数据生命周期、安全等级、质量规则)
     - 制定元数据采集、存储、使用、维护规范
  4. **指标数据标准**:
     - 梳理企业核心指标体系(经营指标、运营指标、财务指标)
     - 统一指标定义口径、计算公式、数据来源
     - 建立指标分层体系(原子指标→衍生指标→复合指标)
     - 制定指标管理规范(新增、变更、下线流程)
- 输出: 数据标准体系文档(含四类数据标准定义和管理规范)

### 步骤4: 数据质量管理体系建设
- 输入: 数据资产盘点结果 + 质量评分 + 数据标准体系
- 处理:
  1. 建立数据质量六维度评估模型:
     - **完整性**: 数据记录是否齐全,关键字段空值率
     - **准确性**: 数据值是否正确反映真实业务情况
     - **一致性**: 跨系统同一数据是否一致,数据口径是否统一
     - **时效性**: 数据是否及时更新,是否满足业务时效要求
     - **唯一性**: 是否存在重复记录,主键是否唯一
     - **合规性**: 数据采集和使用是否符合法规和标准要求
  2. 为每个数据资产制定质量评估指标和阈值:
     - 定义每类数据资产的六维度质量评分标准
     - 设定质量合格阈值(如完整性≥95%、准确性≥98%)
     - 建立质量评分等级(优秀/良好/合格/不合格)
  3. 构建数据质量规则库:
     - 空值检查规则、格式校验规则、范围校验规则
     - 跨表一致性校验规则、跨系统比对规则
     - 重复检测规则、关联性校验规则
     - 业务逻辑校验规则、合规性检查规则
  4. 设计数据质量闭环管理流程:
     - 质量监控(自动+人工) → 问题发现 → 问题分析 → 问题修复 → 质量验证 → 持续改进
  5. 设计数据质量报告机制(日报/周报/月报)
- 输出: 数据质量管理体系文档 + 质量规则库(JSON)

### 步骤5: 数据安全与合规体系设计
- 输入: 数据资产盘点结果 + 行业监管要求 + 治理体系架构
- 处理:
  1. 数据安全分级分类:
     - 按敏感程度分为公开数据、内部数据、敏感数据、核心数据四级
     - 制定各级数据的识别标准和分类规则
     - 对数据资产进行安全分级标记
  2. 数据安全管控措施:
     - **存储安全**: 加密存储、数据库审计、备份恢复
     - **传输安全**: 传输加密、VPN/专线、API鉴权
     - **使用安全**: 访问控制(基于角色的权限管理)、数据脱敏(动态/静态脱敏)、操作审计
     - **共享安全**: 数据共享审批流程、数据使用协议、共享数据脱敏
  3. 合规管理:
     - 对照《数据安全法》《个人信息保护法》等法规要求
     - 个人信息保护: 收集告知、使用授权、最小化采集、隐私影响评估
     - 行业合规要求: 金融(银保监)、医疗(HIPAA)、电信等行业专项合规
     - 数据出境合规: 跨境数据传输评估与合规
  4. 数据安全事件应急响应机制
- 输出: 数据安全与合规体系设计文档

### 步骤6: 数据治理组织架构设计
- 输入: 治理体系架构 + 企业组织现状
- 处理:
  1. 设计三级数据治理组织:
     - **决策层 - 数据治理委员会**: 由高管(CEO/COO/CIO)牵头,各业务部门负责人参与,负责数据治理战略决策、资源审批、重大问题裁决
     - **管理层 - 数据治理办公室(DGO)**: 设首席数据官(CDO)或数据治理负责人,配备专职治理人员,负责治理体系运营、标准制定、质量监控、培训推广
     - **执行层 - 数据Owner与数据Steward**: 数据Owner由业务部门负责人担任,负责本域数据资产的管理决策;数据Steward由业务/技术人员担任,负责日常数据标准执行、质量维护、问题处理
  2. 定义各角色的职责、权限、考核指标:
     - 数据治理委员会: 治理战略审批、资源分配、跨部门协调
     - CDO/DGO: 治理体系规划、标准制定、质量监控、团队管理
     - 数据Owner: 数据资产决策、标准确认、质量问题响应
     - 数据Steward: 数据标准执行、质量检查、问题处理、元数据维护
  3. 设计数据治理考核机制:
     - 将数据质量指标纳入部门和个人KPI
     - 设立数据治理红黑榜和奖惩机制
     - 建立数据治理年度评优机制
- 输出: 数据治理组织架构设计文档

### 步骤7: 数据治理实施路线图与投资估算
- 输入: 全部前置输出 + 战略目标与约束
- 处理:
  1. 制定分阶段实施路线图(通常3-4个阶段):
     - **第一阶段 - 治理启动期(1-3月)**: 成立治理组织、制定治理总纲、启动主数据标准建设、部署治理平台基础
     - **第二阶段 - 体系建设期(4-8月)**: 完成四类数据标准、建立质量规则库、上线质量监控、实施安全分级
     - **第三阶段 - 深化运营期(9-15月)**: 数据质量持续改进、元数据全链路管理、数据资产目录运营、安全合规深化
     - **第四阶段 - 价值释放期(16-24月)**: 数据资产化运营、数据服务能力建设、治理体系优化迭代
  2. 定义每个阶段的里程碑和交付物
  3. 投资估算:
     - 人力投入: 治理团队人员配置与成本估算
     - 平台工具: 数据治理平台采购/建设费用
     - 咨询服务: 外部咨询与实施服务费用
     - 培训推广: 培训与变革管理费用
  4. 预期收益分析:
     - 直接收益: 数据质量提升减少的纠错成本、数据集成效率提升、数据重复建设减少
     - 间接收益: 决策效率提升、合规风险降低、数据资产价值释放、AI应用基础夯实
     - ROI估算(投资回报率)
- 输出: 实施路线图 + 投资估算与收益分析

### 步骤8: 汇总报告输出
- 输入: 全部步骤输出
- 处理:
  1. 按德勤数据治理咨询报告逻辑组织内容
  2. 确保各部分结论一致、逻辑连贯
  3. 补充战略洞察、行业对标、案例引用等咨询级内容
  4. 生成完整的咨询报告 + 体系设计书 + 质量规则库
- 输出: 数据治理咨询报告(markdown) + 附件

## 第一章 数据治理现状诊断

### 1.1 诊断方法与框架

本报告采用 **数据治理成熟度模型(DGMM)**,从六个维度对企业数据治理水平进行系统评估。该模型参考 DAMA-DMBOK(数据管理知识体系指南)框架,结合德勤数据治理成熟度评估方法论,将每个维度的成熟度划分为五个等级:

| 等级 | 名称 | 特征描述 |
|------|------|---------|
| L1 | 初始级 | 无正式的数据治理活动,依赖个人经验,数据管理无序 |
| L2 | 可重复级 | 有初步的数据管理活动但未形成体系,依赖局部最佳实践 |
| L3 | 已定义级 | 数据治理体系已定义,组织、制度、流程基本建立但执行不充分 |
| L4 | 已管理级 | 数据治理体系有效运营,有量化管理和持续改进机制 |
| L5 | 优化级 | 数据治理体系成熟优化,数据资产化运营,持续创新 |

### 1.2 数据治理成熟度评估结果

#### 1.2.1 六维度成熟度评分

| 治理维度 | 当前等级 | 目标等级 | 得分(1-5) | 行业平均 | 差距分析 |

### 2.2 组织层设计

#### 2.2.1 三级数据治理组织架构

**第一级:数据治理委员会(决策层)**
- **组成**: CEO或COO任主席,CIO/CDO任副主席,各业务部门负责人为委员
- **职责**: 
  - 审批数据治理战略、规划和重大政策
  - 审批数据治理年度计划和预算
  - 裁决跨部门数据治理重大争议
  - 评估数据治理成效
- **运作机制**: 每季度召开一次正式会议,重大事项可临时召集

**第二级:数据治理办公室(管理层)**
- **组成**: 首席数据官(CDO)或数据治理负责人领导,配备 {N} 名专职治理人员
- **职责**:
  - 制定数据治理体系方案和各项管理制度
  - 组织数据标准制定、发布和维护
  - 实施数据质量监控和问题管理
  - 组织数据安全分级和合规检查
  - 运营数据治理平台和工具
  - 组织数据治理培训和宣贯
- **运作机制**: 日常运营,周例会+月度报告

**第三级:数据Owner与数据Steward(执行层)**
- **数据Owner**(每个数据域1名,由业务部门负责人担任):
  - 确认本域数据标准和管理规范
  - 决策本域数据的创建、变更、共享、销毁
  - 对本域数据质量负最终责任
- **数据Steward**(每个数据域1-3名,由业务骨干或技术人员担任):
  - 执行数据标准,维护数据质量
  - 处理数据质量问题,跟踪问题闭环
  - 维护元数据和数据血缘
  - 响应数据需求

### 4.1 数据质量评估模型

#### 4.1.1 六维度质量评估框架

| 质量维度 | 定义 | 评估指标 | 计算方法 | 合格阈值 |
|---------|------|---------|---------|---------|
| 完整性 | 数据记录是否齐全,关键字段是否为空 | 字段填充率 | (非空记录数/总记录数)×100% | ≥95% |
| 准确性 | 数据值是否正确反映真实业务情况 | 数据准确率 | (正确记录数/抽样记录数)×100% | ≥98% |
| 一致性 | 跨系统同一数据是否一致 | 跨系统一致率 | (一致记录数/比对记录数)×100% | ≥99% |
| 时效性 | 数据是否及时更新,满足业务时效 | 数据及时率 | (按时更新记录数/应更新记录数)×100% | ≥95% |
| 唯一性 | 是否存在重复记录 | 记录唯一率 | (去重后记录数/原始记录数)×100% | ≥99.5% |

## 第五章 数据安全与合规体系

### 5.1 数据安全分级分类

#### 5.1.1 数据安全分级标准

| 安全等级 | 等级名称 | 数据特征 | 典型数据 | 管控要求 |
|---------|---------|---------|---------|---------|

| L3 | 敏感数据 | 泄露将造成较大损失或合规风险 | 个人信息、商业秘密、合同数据 | 加密存储+访问控制+操作审计 |
| L2 | 内部数据 | 仅限企业内部使用 | 内部报告、运营数据、流程数据 | 访问控制+使用记录 |
| L1 | 公开数据 | 可对外公开 | 官网信息、公开报告 | 基础管理 |

#### 5.3.2 个人信息保护专项

- **收集合规**: 个人信息收集需明确告知收集目的、方式和范围,取得个人同意
- **使用合规**: 个人信息使用不得超出收集时告知的目的范围
- **存储合规**: 个人信息存储期限不超过实现处理目的所必要的最短时间
- **共享合规**: 向第三方提供个人信息需取得个人单独同意
- **权利保障**: 建立个人信息查询、更正、删除、导出的响应机制

## 降级策略

- **数据资产盘点结果不完整** → 基于已有盘点结果进行治理诊断,对缺失部分基于行业最佳实践推断,标注"推断数据"
- **企业数据现状信息不足** → 基于行业平均水平设定治理基线,在报告中标注"行业推断",建议企业补充数据后更新评估
- **行业监管要求不明确** → 按通用法规(数据安全法、个保法)进行合规设计,提示企业补充行业专项法规后完善
- **现有治理基础信息缺失** → 假设当前治理成熟度为L1(初始级)进行体系设计,在诊断中标注"基于假设"
- **投资预算约束未知** → 提供高/中/低三档投资方案,由企业根据预算选择
- **某步骤执行异常** → 跳过该步骤,在报告中标注"待补充分析",不影响其他步骤执行
